| 右侧属性栏 | 演出绑定 + 音符 + 图层 + 工程名 + 画板 + 输出 + 节拍 + 试玩规则全部纵向堆叠 | 按「当前选中对象」只显示相关内容，工程级设置移到独立对话框 |

### 2. 作为常规编辑软件的缺陷

1. **布局写死**：`grid-template-rows: 88px 1fr 302px 27px`、列 `220px 1fr 250px`。1600×1200 窗口下画布只有 1130×622（约 37%），时间轴一屏只能看到 6 轨中的 3–4 轨。
2. **没有任何偏好持久化**：全项目没有用到 `localStorage`，吸附模式、缩放、最近文件、面板状态每次启动都重置。
3. **没有菜单、右键菜单、快捷键表**：`Menu.setApplicationMenu(null)`，右键处理为 0 处。快捷键只能靠读 README。
4. **Delete 键行为取决于右侧打开的是哪个标签页**（镜头页删关键帧、音效页删音效、否则删音符或图层），容易误删。
5. **数值输入**：全部是失焦提交的 `<input type=number>`，不能拖拽、滚轮、方向键步进；显示未格式化（实际看到 `1387.45387453`、`2.846529`）。
6. **画布没有变换控件**：图层只能拖动位置，缩放/旋转只能填数字；没有图层多选、缩略图、搜索、独显。
7. **没有自动保存和崩溃恢复**；关闭窗口只有「返回保存 / 不保存并退出」。
8. **画布持续满帧重绘**：Pixi ticker 每帧都渲染，静止时也占满 GPU。
9. **没有「玩家实际看到的画面」**：界面标着「1920 × 1080 输出」，但预览和试玩显示的是整块画板，没有输出取景框。这同时影响镜头编辑和谱面摆放。
10. 导入是全屏模态遮罩；没有安装包与导出（已知）。

### 3. 作为音游谱面编辑器的缺点

1. **时间轴导航弱**：没有滚轮缩放/平移、播放时不跟随播放头、没有方向键按拍步进、没有循环区间、没有小节标尺（只有分:秒）。
2. **没有变速播放**（0.5× / 0.75×），这是对谱的基本工具；没有节拍器。
3. **细分缺三连音**：只有 1/4–1/64 音符，没有 1/3、1/6、1/12。
4. **没有默认打击音**，也没有按段落切换音色的机制。
5. **Slider 只有匀速单程**：没有时间节点、判定节点、往返。
6. **音符摆放辅助缺失**：没有位置网格吸附、间距吸附、镜像/翻转/旋转/缩放所选。
7. **试玩反馈少**：没有连击、准确率、偏早/偏晚分布；没有音频/输入延迟校准。
8. **没有谱面检查**：重叠音符、出界、落在音乐之外、离拍、Slider 过快、失效绑定都没有提示。
9. **规模化不友好**：绑定音符靠下拉框（「Circle #37 · 命中成功」），281 个音符时一个下拉有约 700 项；159 条演出绑定的列表一次只显示 3 条。
10. 没有全曲密度概览、书签/段落标记。

## 二、六个问题的回答与方案

### 问题 1：250 MB PSD 卡顿——优化编辑器还是精简 PSD？

**结论：两边都做，但主要应该优化编辑器。** 250 MB 在你设定的工作规模内，文档层完全撑得住，瓶颈在渲染和导入管线。

**实测（合成 PSD 217 MB，6000×8000，80 像素层 + 8 分组；8 核 Xeon，无独立显卡）**

| 环节 | 结果 | 判断 |
| --- | --- | --- |
| 导入 | 独立跑 24 s，编辑器内 29 s；后台进程峰值约 750 MB；生成 1325 个分块共 290 MB | 单线程。PNG 编码占 49%，写文件占 12% |
| 单次编辑命令（含全量校验） | 中位 6 ms | 不是瓶颈 |
| 工程 JSON | 1.4 MB，序列化 24 ms | 不是瓶颈 |
| 保存 | 每次重算全部素材的 SHA-256；按同样方式对 507 MB 实测约 1 s（机械硬盘会更慢） | 可优化 |
| 100% 缩放、画布仅 1130×622 | 受管纹理已占 176 / 192 MiB 预算 | 1440p/4K 屏会超预算，触发降清晰度和反复换入换出 |

原稿测试机没有独立显卡，因此没有将它的帧率作为作者机器的预期表现。

**代码推断的主要卡顿来源（按我估计的影响排序）**

1. **拖动图层时每次鼠标移动都重建整个场景**：`editor.ts` 的 `moveSelected` 每次传入新的 `layers` 对象，`LayerScene.setProject` 发现引用变化就 `clear()` 后全部重建（容器、滤镜、精灵）。
2. **每个图层单独绘制**：即使 80 层里只有 10 层有演出，其余 70 层也逐层叠画，放大后是 80 层的过度绘制。
3. **每个隔离分组 / 混合模式 / 剪贴组 / 蒙版层各占一次全视口滤镜通道**，每帧执行。
4. **纹理预算固定 192 MiB**，不随显卡调整。
5. **分块读取路径长**：IPC → 整文件读入 → SHA-256 → 拷贝 → PNG 解码，并发 4。
6. **静止时也每帧重绘**。

**你的性能记录分析（插画64.psd，263 MB，6116×5488，102 像素层 + 6 分组）**

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| 静止时帧率 | 36 FPS（平均 27 ms，P99 50–59 ms） | 当时并未播放、视图是「适合窗口」（缩放 6%），画布只有 956×409。4060 在这种负载下应稳定 60+ |
| 每帧合成滤镜通道 | 81 个（含 14 个剪贴组、6 个隔离分组） | 每个都是一次全视口离屏渲染，每帧执行，估算 285 MB 临时缓冲。这是帧率低的主因 |
| 受管纹理 | 193 个 / 167 MB，预算 192 MB | 在 6% 缩放下已接近上限；2560×1600 放大查看时会超预算并降清晰度 |
| 显卡信息 | 记录里没有 | 现有记录不采集 GPU 型号，无法确认用的是核显还是 4060 |

**闪烁的直接原因（读代码确认的机制）**

1. 缩放跨过清晰度级别时，旧级别的分块精灵立即销毁，新级别分块要异步读取解码后才出现，中间几帧是空的。
2. 开关图层、拖动图层会触发整个图层场景清空重建，重建后的第一帧没有精灵。
3. 双显卡笔记本上，Electron 默认可能跑在 Intel 核显上，会进一步放大以上问题。

**阶段 2 的候选措施**

- E0：先把实际 GPU 型号写入运行记录；若需要切换显卡，在后续任务验证高性能显卡请求方式及实际效果。
- E1 扩展为「无闪烁更新」：新级别分块就绪前保留旧级别显示；图层开关、拖动、属性变化只更新对应图层，不再整场景重建。
- E8（2c）：在画面等价的前提下减少重复离屏合成。当前代码已有普通分组直接绘制路径；是否还能省去通道，需要连同子层混合、隔离、整体透明度和蒙版一起判断，不能只看分组是否为正常模式且不透明。跨帧缓存静态结果留给 E5。
- E4：后续评估纹理预算。原稿的「8 GB 独显给 1 GB」是候选配置，需结合实际资源占用验证。

**编辑器侧方案**

| 编号 | 改动 | 规模 | 预期效果 |
| --- | --- | --- | --- |
| E1 | 拖动/属性变化改为按图层 id 增量更新；切换清晰度时保留旧分块，待新分块就绪再替换 | 小–中 | 消除清空重建和分块切换造成的闪烁 |
| E2 | 按需渲染：未播放且无变化时停止持续重绘；变化或素材就绪时恢复更新 | 小–中 | 减少静止时的无效绘制 |
| E3 | 分块改走自定义协议流式读取；哈希每会话只校验一次；并发提到 8 | 小–中 | 缩放/平移时分块出现更快 |
| E4 | 纹理预算按设备自适应（设置项 256 MB–2 GB），按屏幕覆盖面积排优先级 | 小 | 大屏不再频繁降清晰度 |
| E5 | **静态图层烘焙**：没有演出绑定且未被选中的连续图层，自动合成为一组缓存纹理，编辑到其中某层时失效重烘 | 中–大 | 绘制量和滤镜通道减少最多，收益最大 |
| E6 | 先做可继续编辑的后台导入，再按测量结果决定并行化 | 中 | 降低等待影响；原稿估计导入可降到 1/3–1/5，尚未验证 |
| E7 | 保存时跳过本会话未变化的素材哈希 | 小 | 保存接近即时 |

近期 2a 只做 E1、E2 与 GPU 信息记录。分块/纹理/保存、减少滤镜、静态烘焙、后台导入分别安排，按复测和试用结果决定先后。

**怎样判断优化有效（暂缓建议，不作为当前验收门槛）**

拿同一份 PSD，在同一台电脑、同样窗口大小和缩放下，重复同一组操作。就像给同一条路修路，修前修后都走这一段，才知道是否顺畅。

| 实际操作 | 想改善的体验 | 执行者留下的证据 |
| --- | --- | --- |
| 连续拖动、开关图层、缩放 | 画面跟手，不闪白、不忽然消失，也少出现停顿 | 同操作录屏和画面更新耗时，单独看最慢的那些更新 |
| 放着不操作，等素材加载完成 | 编辑器减少无用工作，操作时又能立即响应 | 静止时实际重画次数和资源占用 |
| 保存或导入 | 等待更短，结果完整 | 同一类保存/导入的实际用时，区分首次保存与再次保存 |
| 重复操作一段时间 | 不因越用越占资源而变慢，画面内容正确 | 内存等资源记录，以及相同时间点的画面对照 |

例如「保存从 3 秒变为 1 秒」容易理解和比较；这里的数字只是示例，不是实测或承诺。静止画面不用反复重画，因此不能要求静止帧率越高越好。技术数字由执行者记录并解释，糖糖主要看操作是否顺畅、画面是否正确。这套采样与比较方式已暂缓，未来需要时再讨论。

**PSD 侧建议（现在就能做，不用等编辑器）**

- 只把**需要单独做演出的部件**保留为独立图层/分组，其余合并。
- 画布分辨率按「输出分辨率 × 最大镜头放大倍数」估算：1920×1080 输出、镜头最多放大 2.5×，长边约 4800 px 就够；6000×8000 以上只有放大超过 3× 才用得上。
- 图层样式、调整图层、智能对象先栅格化（编辑器本来就不重建这些，只会给兼容提示）。
- 删除隐藏的草稿层；保持 8 位 RGB。

**已补充**：卡顿出现在缩放、开关图层、拖动图层时；机器与性能记录的结论见上面的「你的性能记录分析」。

### 问题 2：图层演出预览小窗口

**目标**：调参数时不用移动主播放头，就能循环看到这一条演出的效果。

**分批交付**：3a 先做停靠小窗、单条绑定独立循环、进度拖动和参数即时刷新。3b 再按反馈选做浮动、背景切换、多绑定、失败模拟、悬停预览与音效试听。下面保留完整候选设计，不要求一次做齐。

**交互设计**

- 位置：默认停靠在演出属性区顶部；可弹出为浮动小窗，可拖动、可改大小，位置和大小记住。
- 内容：自动取景到目标图层包围盒（留边），可切换「仅目标图层 / 带背景（压暗）」。
- 播放：循环播放「前摇 0.5 s → 演出 → 停留 0.5 s」；有进度条可拖；速度 0.25× / 0.5× / 1×。
- 范围：当前选中的绑定 / 该图层的全部绑定 / 该音符触发的全部绑定。
- Slider 跟随类演出提供「完整追踪 / 中途松键 / 晚按」三种模拟，直接看到失败时的样子。
- 改参数即时刷新；在「显现方式」下拉上悬停某一项即可预览，不必先应用。
- 可选同时试听绑定的音效。
- 现有面板底部的「进度覆盖滑杆 / 跟随播放头」并入小窗的进度条。

**技术路线**

- 复用 `core/reveal.ts` 的 `RevealEvaluator`（已是纯时间求值）和一个模拟的 `PlaybackTake`，给小窗独立的本地时钟。

- 新增：`renderer/reveals/PreviewWindow.vue`、`reveals/preview-scene.ts`；`LayerScene` 需要支持「只构建某个子树」。

### 问题 3：镜头编辑不直观

**现状问题**

- 关键帧是一串「46.347 秒 · 1.45×」文字列表，改动全靠 X / Y / 缩放 / 旋转 / 中心 X / 中心 Y 六个数字框。
- 一个关键帧绑定全部属性和一个缓动，做不到「位置慢慢移动的同时，缩放按拍脉冲」。
- 时间轴镜头轨只有一条线上的菱形，看不出每段在动什么、用了什么缓动。
- 画布上的黄色预览框是整块画板，不是 16:9 的输出画面。
- 「位置」和「缩放中心」是两个独立概念，直觉上难以预测结果。
- 自定义缓动只能拖一条贝塞尔或填四个数，没有预设。

**参考对象**

| 软件 | 借鉴点 |
| --- | --- |
| DaVinci Resolve · Dynamic Zoom | 在画面上直接摆「起始框 / 结束框」 |
| After Effects / Premiere | 每个属性一条关键帧轨、自动关键帧、图表编辑器 |
| 剪映 | 菱形按钮加帧、上一帧/下一帧跳转 |
| Re:PhiEdit（Phigros 谱面编辑器） | 按属性分层的事件 + 缓动预设库，音游圈通行做法 |
| Blender / Godot | 取景框控件、运动路径、相机视角与导演视角切换 |

**方案：以取景框为中心的镜头编辑**

1. **输出取景框**：镜头在画板上显示为一个输出比例（如 16:9）的矩形。框内拖动 = 平移，拖角 = 缩放，角外拖动 = 旋转；吸附到图层中心和边缘。界面上不再单独暴露「缩放中心」，但必须先明确中心含义和控件换算规则。
2. **两种视角**：「导演视角」看整张画板和取景框；「镜头视角」只看玩家实际画面（带黑边）。试玩默认用镜头视角。
3. **前后帧虚影与运动路径**：上一帧和下一帧的取景框画成细线框，框中心之间画路径，按拍打点，疏密即速度。
4. **自动关键帧**：开关打开时，在没有关键帧的时间点调整镜头会自动加帧（现在滚轮缩放已经这样做，但没有明示）。配「◀ 上一帧 / ◆ 加帧 / ▶ 下一帧」按钮和快捷键。
5. **镜头轨展开为子轨**：位置、缩放、旋转、震动各一条。两个关键帧之间画成带缓动名称的色条。支持框选、多选、复制到播放头、Alt 拖动复制、整体拉伸。
6. **曲线与缓动预设**：选中一段后展开曲线编辑器；提供预设面板（线性、Sine / Quad / Cubic / Expo / Back / Elastic / Bounce 的 In / Out / InOut，带缩略曲线）。Back / Elastic / Bounce 无法用单条贝塞尔表示，需要扩展 `Easing` 类型。
7. **按拍生成的镜头预设**：选一段时间范围，一键生成「每拍缩放脉冲」「推近」「拉远」「横摇」「震动」。
8. **属性框改用可拖拽数值控件**（见问题 6）。

**已确认**：关键帧拆成位置 / 缩放 / 旋转三条通道，旧工程不要求迁移。

**先明确再实现**：现有 `CameraEvaluator` 会插值 `pivot`（缩放中心），`cameraMatrix` 同时使用位置、缩放、旋转和中心计算画面。重设计时须明确中心是固定、由取景框推导，还是随某条通道变化，不能只删掉输入框而保留未说明的运动行为。用「平移同时缩放并旋转」的短样例核对关键帧之间的连续运动、取景框与实际画面的一致性，以及绑定到图层的 Slider 是否仍然贴合。取消旧工程兼容不影响这些新功能自身的正确性要求。

### 问题 4：Slider 的等时节点

**已确认的规则**

- 只有一种节点；判定、音效/事件、定时是它的作用，不划分自动节点、手动节点或另一种定时节点。
- 同一条 Slider 内相邻节点的音乐时间间隔相同，例如每隔 0.5 秒经过一个。这里的等时指实际时间，不是跨 BPM 变化时仍按固定拍数排列。
- 节点在路径上的位置可以调整，顺序沿路径前进。因此节点之间可以长短不同，光点在每一段以对应速度移动，并准时到达下一个节点。等时间隔不要求路径距离相等。
- 不允许单独拖动某一个节点的时刻而破坏等时规则；节点时间从统一规则推导。
- 完成判定增加「按节点命中数」。

| 作用 | 含义 |
| --- | --- |
| 判定 | 在节点时刻检查有效追踪，记录命中或漏掉 |
| 音效 / 事件 | 区分「光点经过」「节点命中」「节点漏掉」的用途；试听与试玩按各自规则读取同一套节点 |
| 定时 | 节点规定光点在对应时刻到达的路径位置，节点之间分段匀速，白色描线跟随同一进度 |

**交付与实现边界**

- 5a 完成统一节点、路径位置调整、画布/时间轴显示、判定、完成统计和基本节点音。5b 再接图层演出等事件联动，复用同一节点模型。
- 工程只保存一套有稳定标识和顺序的节点，以及统一的时间规则。取消原稿 `ticks` 与 `nodes` 两套来源、逐点独立时刻和 `pin` 分类，具体字段在实施时确定。

### 问题 5：给 Circle 和 Slider 加伴奏打击乐音效的建议

**先交付默认打击音，再扩展音色组**

6a 先提供工程默认的 Circle 命中、Slider 起点、Slider 完成等基础槽位、音符覆盖/静音和一套起步音色；节点音在统一节点模型就绪后接入。6b 再按需要扩展：

- 一个音色组包含固定槽位：Circle 命中、Slider 起点、Slider 节点、Slider 追踪中（持续音）、Slider 完成、漏掉（可空）。
- 工程有一个默认音色组，音符默认继承；单个或批量音符可以改用其他组、叠加「附加音」、或静音。
- 时间轴上加「音色区段」：主歌用轻沙锤，副歌换雪橇铃 + 铃鼓，整段切换（相当于 osu! 按时间点切换音色）。
- 现有逐音符绑定继续有效，且优先于默认。

这样可减少逐音符重复绑定；原稿中《グッバイ宣言》的 337 条片段只是工作量参考，不要求迁移该旧工程。

**乐器与动作的对应**

| 动作 | 需要的声音特征 | 推荐乐器 |
| --- | --- | --- |
| Circle 普通点击 | 起音快、短、无尾音 | 沙蛋/沙锤单击、木鱼、响板、卡巴萨单击、闷音三角铁、响指、闭镲 |
| Circle 重拍/副歌 | 更亮、略长 | 雪橇铃单击、铃鼓拍击、开放三角铁、拍手 |
| Slider 起点 | 与 Circle 同族、略轻 | 同上，音量低约 2 dB |
| Slider 追踪中 | 连续颗粒感，松键即停 | 雪橇铃连摇、沙锤连摇、铃鼓滚奏、雨声筒、风铃串 |
| Slider 节点 | 轻、短，构成 8 分/16 分律动 | 轻沙锤、踩镲、三角铁轻击，比主音低约 6 dB |
| Slider 完成 | 有「收束」感 | 开放三角铁、指钹、风铃上行、bell tree |
| 描线完成 → 图层显现 | 闪亮 + 轻微低频 | 风铃串 + 很轻的底鼓 |
| 漏掉 | 不惩罚 | 不发声，或极轻的闷响 |

**让它听起来像伴奏而不是提示音的规则**

1. **默认用无固定音高的打击乐**（沙锤、雪橇铃、铃鼓、卡巴萨、拍手），任何调的歌都不会冲突。有音高的（钟琴、卡林巴、手铃）只在音色组设置了移调、对上歌曲调性时使用。Web Audio 的 `detune` 可以直接实现移调。
2. **占高频位置**：主要能量放在 2–10 kHz，300–500 Hz 以下切掉，避开人声和贝斯。这样不用开大音量也听得清。
3. **起音对齐**：沙锤类采样常有「唰」的前摇，听感上的拍点在峰值而不是文件开头。导入时自动检测采样起音并裁掉前导静音（项目已有起音检测）；点击类槽位只用「击」的奏法，不用「摇」的奏法。
4. **避免机关枪效应**：每个槽位支持 3–5 个轮换采样，加 ±1–2 dB 音量、±20 音分音高的微小随机。随机用音符 id 做种子，保持项目「可重复求值」的原则。
5. **判定差异**：Perfect 用更亮的一层，Good 用更软的一层，反馈自然不刺耳。
6. **持续颗粒音优先复用节点事件**：按该 Slider 的统一等时间隔发声，不另按 16 分音符生成一套节点。真正的持续循环留给风铃、雨声筒等音色，后续按需要扩展。
7. **声像**：按音符 X 位置做 ±0.3 的轻微左右偏移（`pan` 字段已有）。
8. **防过载**：打击通道末端加一个限幅器；同槽 30 ms 内重复触发合并。
9. **响度**：打击音峰值比音乐低 6–12 dB 起步，试玩时可调。

**素材来源**

- 内置一套**程序合成的起步音色组**（噪声 + 带通 + 包络做沙锤，非谐波分音做铃类），没有授权风险，体积小。
- 支持导入你自己的采样包。
- 需要真实采样时，从 CC0 库里挑（如 freesound 的 CC0 筛选、Versilian VCSL）。具体文件的许可在实施时逐个核对并写入 `THIRD_PARTY_NOTICES.md`；我目前没有核实过具体条目。

### 当前任务

**2c · 减少滤镜通道（已交付，待糖糖验收）**

目标：保持画面和演出效果一致，减少每次绘制中不必要的离屏合成，改善大 PSD 编辑与播放时的绘制开销。

- 开工依据：2b 的真实 PSD 记录仍有 81 个合成滤镜。先核实文档、图层、剪贴组和蒙版各自承担的作用；区分已创建的滤镜数量与实际执行的合成次数，不能将现有数量或估算缓冲直接当作每帧开销或总显存。沿用已有运行记录作必要观察，不另建通用性能平台或新增帧率、提速倍数门槛。
- 优化入口：当前 `LayerScene` 已允许无需隔离的普通分组直接绘制，重点检查蒙版外额外包裹的合成、分组及剪贴结构中是否存在可证明等价的重复处理。具体采用哪些直绘或合并路径由执行者根据代码与像素对照决定；复杂组合保留正确的原路径，不预先承诺删掉多少通道。
- 画面规则：保留隔离与穿透分组的差别、子层与背景的混合关系，以及分组透明度只对合成结果生效一次的行为。剪贴不能累加底层透明度；透明画布上的混合不能误用编辑器底色。栅格蒙版、动态显现遮罩和多层嵌套仍须保持正确位置、边缘及组合顺序，不能仅凭分组自身正常模式或透明度为 1 就省去隔离。
- 动态更新：图层显隐、透明度、混合模式、蒙版开关、父子关系及演出状态改变时，直绘与必要合成路径能正确切换；覆盖父组演出、暂停、跳转、变速与循环边界。沿用 2a 的增量场景和分块过渡，不因切换路径每帧重建全场景；删除、撤销、切工程后释放不再需要的滤镜与中间资源。

- 本阶段只优化合成路径，不扩展 PSD 混合模式支持，不改工程格式；跨帧静态烘焙、后台导入和预览小窗分别留在 2d、2e、3a。若某项优化无收益或无法保持画面等价，说明结果与保留原因，不通过降低画质完成指标。

**1d-2 · 变速播放与循环区间**

目标：放慢同一段音乐检查对拍，重复播放选定片段进行演出预览或试玩练习；所有画面、声音及判定仍以同一音乐时间为准。

**变速行为**

- 提供 0.25×、0.5×、0.75×、1× 播放倍率，清楚显示当前速度。沿用原计划直接变速，降速会降低音高，本阶段不做保持音高的时间拉伸。
- 改变倍率不修改音符时刻、工程 BPM、素材元数据或时间轴时长。音乐播放头、音符、镜头、演出和音效事件共同按新倍率推进；0.5× 时实际经过 2 秒，工程音乐时间推进约 1 秒。
- 暂停时改倍率不改变播放位置；播放中改倍率从当前音乐时刻连续切换，不能跳回起点、清掉本轮判定记录或重复发出已触发的事件。取消旧倍率下尚未发声的排程，按新映射重新安排。
- 随工程播放的背景音乐与音效采用同一倍率，素材库单独试听保留原速。说明并处理切换倍率时已发声的音效尾音，不能多放一次或留下旧排程。
- 试玩输入与判定窗口继续按工程音乐时间计算，不另改判定数值。普通暂停继续保留本轮记录；更换倍率不是新一轮试玩。

**循环行为**

- 在时间轴提供明确的循环区间拖选区域，显示起点 A、终点 B，支持调整端点、启用/停用和清除。选择区间不移动音符或片段，也不误触播放头拖动、平移及右键菜单；端点使用既有节拍吸附规则并保留临时绕过方式。
- 区间限制在音乐范围内且 A < B；反向拖选归一为前后顺序，无效或过短区间不能启用。最小跨度根据现有时间精度和实际音频排程能力确定并说明，不做高频卡死的零长度循环。
- 启用循环后，从区间外开始播放时回到 A；在区间内则从当前位置继续，到 B 后回到 A。暂停冻结当前位置，关闭循环后正常播放到曲尾。手动定位到区间外时暂停循环约束并在界面说明，通过重新启用循环返回该区间，避免播放头立刻被抢回。
- 编辑预览与试玩均可循环。每次回到 A 视为新一轮：清理上一轮命中/跟随/粒子等实际记录及音效排程，不继承按住输入，也不把前一轮的成功带入下一轮；不得伪造 A 之前的命中来补全跨边界 Slider。
- 循环起点上的事件每轮只触发一次；终点处恰好完成、跨越 A/B 的 Slider 及演出须明确一致的收尾规则并验证。被区间截断的跟随不能伪造为完成，上一轮待播音效和尾音不能串入下一轮。
- 变速和循环是本次编辑/练习的播放设置，不写入 `.rcproj`、不占用工程撤销或触发未保存标记。首次默认 1×、循环关闭；切工程或更换音乐时清除区间并回到该默认状态，防止沿用上一首的练习范围。

**实现前核对**

- `AnchoredClock` 当前按音频上下文时间一比一推进；`AudioTransport.contextTimeAt()` 同样假定 1×，`SoundEngine` 用它安排音效。必须统一正反向时间映射、输出延迟和预排程时域，不能仅修改音乐 source 的播放速度。
- 当前普通 `editor.seek()` 以 `seek` 原因重置，`PlaybackTake` 会保留跳转之前的部分记录；循环需要新一轮语义，不能直接等同于普通后跳。复用现有轮次、输入释放和排程失效机制，明确一次切换的执行顺序。
- 音频循环不能只靠界面每帧检测超出 B 后才重启。以音频时钟安排边界并正确处理越界量、短区间与 UI 更新延迟，避免多轮后持续漂移；页面隐藏或失焦沿用既有暂停行为。主线程恢复后不能补播一串已经过去的声音。
- 播放、暂停、定位、变速、切工程及异步音效准备可能交错；晚到的准备或播放请求不能把旧工程、旧倍率、旧轮次重新启动。保持 1d-1 的跟随与定位和 1c 命令入口一致。
- 本阶段不增加时间拉伸、默认音色组、节拍器、成绩历史、自动谱面拉伸或新的 Slider 节点；需要改变已有产品规则且超出上述范围时带具体方案对齐。

**验收场景**

1. 在四种倍率下观察与试听已知拍点，音乐、音符、演出和音效对齐；比较工程时间推进与音频时钟。播放中切倍率及暂停后改倍率都不跳位置、不重复触发，回到 1× 后正常。
2. 拖选、调整、启停和清除循环，连续运行多轮；起点音效每轮一次，终点之后的声音不提前排入本轮。覆盖曲首、曲尾、短区间、BPM/拍号变化、手动区间外定位以及暂停继续。
3. 试玩一轮成功、下一轮漏点或松键，结果和演出各自正确；验证跨边界 Slider、终点恰好完成及按住输入跨循环时的状态，不能从上一轮继承成功或留下卡住按键。
4. 快速切换播放/暂停、倍率和工程，打开帮助或恢复弹窗并切出窗口，声音与输入能正确收尾；关闭循环恢复正常播放结束逻辑。
5. 用真实 PSD 短谱面复查导航、布局、右键、保存重开与自动恢复。变速和选区不修改工程内容或标记未保存，切歌与换工程清除练习状态。

执行 `npm run check`、时钟映射/边界/排程与轮次隔离的针对性测试、相关真实音频与窗口回归；按流程安排独立审查。提供可听到变速和循环效果的录屏或等效音频证据，以及简短验收清单；只看播放头动画不足以证明声音同步。技术验证由执行者完成，不重启已暂缓的通用性能量化方案。更新 PR 和计划后停下。

**1d-1 · 时间轴导航与节拍定位**

目标：快速浏览曲子、精确定位节拍，播放时能持续看到播放头。这次只改导航和节拍显示，变速与循环另作 1d-2。

- 调整时间轴显示不改变已有音符时刻、工程 BPM/拍号或 Slider 节点设计；本阶段不新增拍号编辑器、变速、循环、节拍器、书签或轨道内部高度调整。遇到原稿未明确的节拍边界行为，在任务内说明采用的规则。

- 左栏、右栏和整个时间轴可分别收起、展开，收起后保留明确的展开入口，并记住各自展开时的尺寸。左侧「图层 / 素材 / 音效素材」三个区块可分别折叠并调整高度。
- 提供「谱面 / 演出 / 镜头」三套布局预设：谱面优先时间轴与音符编辑空间，演出优先图层与属性空间，镜头优先画布空间。具体比例由执行者结合实际窗口试用确定；预设只调整布局，不改变工程内容、播放位置、选中对象或当前工具。
- 提供「专注画布」按钮与快捷键，临时隐藏左右栏和时间轴，再次操作恢复进入前的布局；保留可见的退出入口。采用 Tab 时只在画布操作语境中生效，不抢输入框、下拉框、按钮导航或弹窗的正常按键。
- 布局属于本机偏好，跨工程和重启保留，不写入 `.rcproj`，不触发工程未保存标记或占用工程撤销。只保存一份当前布局与三套内置预设，不扩展自定义工作区管理。
- 提供「重置布局」。窗口变小、显示缩放改变或偏好数据无效时，尺寸限制在可用范围内，画布与展开/重置入口仍可操作。已有界面最小窗口为 1080×720，本阶段不扩大这一最低要求。

**实现前核对**

- 当前 `App.vue` 组合左栏、画布、右栏和时间轴，`style.css` 仍固定三栏宽度和时间轴高度。按职责提取布局状态与分隔条，避免本阶段扩展成全应用重构或完全自由停靠系统。
- `CanvasPanel` 卸载会销毁 `EditorStage`；时间轴有自己的滚动、缩放和波形状态。面板收起、展开或切换布局不能重新创建整个编辑器、重置播放或丢失未提交的输入；明确处理隐藏尺寸为零以及展开后的尺寸刷新。
- 按需渲染必须在尺寸变化时及时更新、结束操作后可重新静止；分隔条拖动不能误触画布编辑、图层排序或数值字段拖动。拖动中取消、丢失指针捕获或切出窗口后不能残留拖动状态。
- 本次调整整个时间轴面板，不改变轨道内部顺序、隐藏规则，也不将图层树的分组展开状态混入新布局偏好。保持 0c 的恢复提示、保存退出和单实例约定可用。

**验收场景**

1. 连续拖动左右分隔条及时间轴高度，画面不空白，控件可用，缩放后点选与拖动对象位置正确；停止操作后仍支持按需静止。
2. 收起每个主面板及左侧三个区块，再展开，尺寸能恢复；能把空间让给其他区块。缩小到当前最小窗口、再放大，画布和恢复入口不被挤出屏幕。
3. 三套预设有清楚的空间分配差异；进入专注画布再返回，恢复原布局。输入数字、切换焦点和操作恢复弹窗时，快捷键不误触。
4. 调整后重启、打开另一个工程，布局保留；单纯调整布局不会标记工程为未保存，撤销仍作用于工程编辑。重置布局及无效偏好回退可用。
5. 带真实 PSD、音符和演出试用，检查播放、时间轴滚动、编辑输入、恢复提示及保存退出；面板折叠、预设切换与播放头、选中状态互不干扰。

执行 `npm run check`、必要的布局窗口检查及受影响的渲染、输入和恢复回归；提供分隔条拖动、折叠、预设、专注画布与重启保留的简短录屏和本机验收清单。普通实现由执行者完成，影响产品行为或范围时再对齐；交付后停下。浮动小窗归 3b，属性栏内容重组归 7a，不在本阶段展开。

**2a · 图层无闪烁更新与按需渲染**

**0c · 基础恢复与保存退出**

目标：异常退出后，可以继续编辑最近自动保留的工程；正常退出时可以直接保存。恢复同时覆盖未命名的新工程和已有工程尚未正式保存的修改。

**范围与行为**

- 每 15 秒检查已提交的修改，有新版本才写恢复快照；拖动预览或其他操作处理中延后到下次检查；不把每次拖拽预览都写入磁盘。失败时保留上一次完整快照并给出可见提示。
- 恢复数据包含工程和可用的引用素材，包括新导入但尚未正式保存的 PSD 分块、图片、音乐和音效。恢复不能依赖已经被清理的临时会话目录。
- 启动后发现可恢复内容时，显示工程名或未命名状态、快照时间，允许恢复、暂不处理或明确丢弃；暂不处理不删除快照。
- 恢复后仍视为有未保存修改，由用户正式保存。自动快照不覆盖原工程文件，不把正式保存状态改成「已保存」；未命名工程第一次正式保存仍选择路径。
- 关闭有修改的工程时，提供「保存并退出 / 不保存并退出 / 取消」。只有保存成功才按保存选项退出；取消文件选择或保存失败都保留窗口和编辑内容。
- 正式保存成功或明确丢弃后，只清理已被该操作处理的恢复内容；保存中产生的更新、其他工程的快照及其所需素材不能误删。恢复内容在再次异常退出后仍可用，直到被成功保存或明确丢弃。

**实现前核对**

- 当前 `ProjectRepository.close()` 会删除会话临时素材目录，`closeAll()` 被窗口关闭流程调用；`editor.adopt()` 切工程时也会关闭前一个会话。必须安排好恢复素材与临时清理的关系。
- 正式保存继续复用文件服务的校验与完整写入流程。快照写入中断不能破坏上一次可恢复内容；素材未完整落盘的记录不能标成可恢复。
- 保存、自动快照、切工程及退出可能交错：绑定工程会话和修改版本，避免迟到结果覆盖新状态、错标已保存或清理仍在使用的素材。具体实现由执行者选择。

**验收场景**

1. 新建未命名工程，导入图片/PSD、音乐和音效并编辑；等待快照完成，强制结束应用。重开能恢复对应编辑，图像和声音素材可用，并能正式保存重开。
2. 打开已保存工程继续修改，快照完成后异常退出。原正式文件保持原保存内容，恢复项包含未保存修改；恢复后仍提示需要正式保存。
3. 分别验证保存并退出、取消退出、取消保存路径、保存失败及明确放弃。成功保存能重开，失败和取消不会关闭窗口或丢弃编辑。
4. 检查快照写入中断、切换工程、恢复后再次异常退出，确认没有损坏上一份快照、恢复错工程或丢失所需素材。

执行 `npm run check` 和相关文件、素材及窗口回归，提供恢复与保存退出的必要录屏；对文件写入、恢复和清理流程安排独立审查。界面显示快照时间，交付说明可恢复到哪次快照，不承诺最后一次按键绝不丢失。现存旧工程仍不要求迁移；最近文件等另属 7c。
